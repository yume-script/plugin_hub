# 🧩 플러그인 허브 (plugin_hub)

BookOasis에 설치된 카테고리 레벨 플러그인의 카테고리 뷰를 **하나의 화면에서 각 플러그인 이름의 탭으로 구분해 통합 표시**하는 플러그인입니다.

## 주요 기능

- **가이드 준수 검사(자동 제외 + 기존 설정 초기화)**: 아래 2가지 규칙 중 하나라도 어긴 플러그인은 허브 탭/설정 표/카탈로그 어디에도 나타나지 않고, 완전히 원래 자기 사이드바 탭 그대로 독립 동작합니다(허브가 그 플러그인의 존재를 아예 모르는 것처럼 처리). **이미 사용 중이던 플러그인**이 나중에 위반 상태가 되면(예: 폴더명 변경, VERSION 파일 삭제), 저장돼 있던 "합치기"/"숨기기" 설정과 탭 순서(`TAB_ORDER_*`)도 기본값으로 되돌려 실제 DB에 저장까지 합니다 — 화면뿐 아니라 저장값 자체를 허브 밖으로 완전히 꺼내는 것입니다.
  1. **클래스 id 규칙**: 클래스에 선언한 `id`가 실제 플러그인 폴더명과 일치해야 함 (`plugins/metadata/<plugin_id>/` 구조 전제)
  2. **VERSION 파일 규칙**: 그 폴더에 `VERSION` 파일이 있고 `{"plugin version": "..."}` 형태의 유효한 JSON이어야 함
  위반 시 서버 로그에 사유가 남고(프로세스당 1회), 기존 설정을 초기화했다면 그 사실도 별도로 1회 로그에 남습니다.
- 사이드바 [플러그인 허브] 진입 시, 표시하도록 선택한 플러그인들을 탭으로 통합 표시
- 모든 세션(일반/성인/오디오/비디오)에 노출되며, 각 보관함에서는 그 세션에 맞게 선택된 플러그인만 표시
- 설정 페이지에서 **카드형 UI**로 플러그인별 표시 세션 선택:
  - 카드마다 플러그인 이름 + 버전(VERSION 파일 파싱) + id 표시
  - 플러그인이 노출 가능한 세션(일반/성인/오디오/비디오)별 체크박스
  - 하나라도 켜면 해당 플러그인의 **개별 사이드바 탭은 자동 숨김** (전부 끄면 원복)
- 마지막으로 본 탭을 세션별로 기억해 재진입 시 자동 복원
- 개별 플러그인이 관리자 화면에서 **정지(비활성화)** 되면(`PLUGIN_ENABLED_<id>` = `0`), 해당 플러그인은 **탭 목록에서만 제외**됩니다. 설정 카탈로그(체크박스 카드)에는 계속 남아있고 **실제 저장된 선택값을 그대로 유지**한 채 체크박스 클릭만 잠깁니다(정지됨 배지 표시) — `save-config`가 설정 전체를 덮어쓰는 방식이라 값을 건드리면 저장 시 소실되므로, 값은 절대 바꾸지 않고 상호작용만 막습니다. 다시 활성화하면 예전 선택이 그대로 복원됩니다.
- **설정 바로가기**: 탭 바 우측 상단의 톱니바퀴(⚙) 아이콘을 누르면 사이드바 "환경설정" → "플러그인 설정" 탭 → 플러그인 허브 카드 아코디언까지 자동으로 이동/펼침 (실제 코어 클릭 경로를 그대로 재현: `#category-settings` 클릭 → `window.switchSettingsTab('plugins')` → 카드 헤더 클릭). 매번 하단까지 스크롤해서 찾을 필요 없음.
- **일괄 합치기/기본으로**: 카드 목록 위 "일괄 합치기" / "일괄 기본으로" 버튼으로 조작 가능한 셀렉트를 한 번에 "허브에 합치기" 또는 "기본"으로 바꿀 수 있습니다. 정지된 플러그인의 잠긴 셀렉트와 "완전히 숨기기"로 지정된 항목은 일괄 처리에서 제외되어 값이 보존됩니다.
- **제외 목록**: 설정 화면 하단 "목록에서 제외할 플러그인"에 콤마로 구분한 플러그인 id를 적으면 해당 id는 허브 카드/탭 후보에서 아예 빠집니다. 기본값(한 번도 저장한 적 없을 때)은 `bookoasis_plugins_viewer`(원본 "플러그인 모아보기") — 허브 안에 또 다른 통합 뷰어가 탭으로 들어가는 걸 방지합니다.

## 동작 원리

- **직접 마운트 방식**: 코어 `mountCategoryPluginUI`와 동일하게
  `innerHTML(css+html)` + `new Function('pluginId','container', js)` 로 각 뷰어를 탭 전환 마운트합니다.
  (iframe 격리 방식은 개별 뷰어가 코어 window 상태에 의존해 폐기)
- 탭 목록은 자체 `get_dashboard_data` 계약(`/api/media/dashboard/widgets/<id>/data`)으로 조회하고,
  각 뷰어의 UI 번들은 `/api/media/plugins/<id>/ui` 로 로드해 캐시합니다.
- 개별 뷰어는 `window.__bookOasisViewerCleanups` 레지스트리로 자체 정리되므로
  탭 전환 시 이전 뷰어의 리스너/옵저버 클린업이 보장됩니다. **기존 뷰어 코드는 0% 수정.**
- **사이드바 숨김**: 통합 표시로 선택된 플러그인은 런타임에 클래스 속성 `category_tab`을
  None으로 오버라이드해 코어 사이드바에서 제외합니다 (파일 무수정, 메모리상 오버라이드,
  선택 해제·재시작 시 원복). 데이터 API는 계속 동작합니다.

## 설정 저장 구조

- 설정 키: `SHOW_<plugin_id>__<session>` (예: `SHOW_bookoasis_11t__adult`) — 불리언
- 저장 위치: general DB `PLUGIN_CONFIG_plugin_hub` (코어 설정 저장 계약 그대로 사용)
- 기본값: 전부 꺼짐 = 기존처럼 개별 탭 표시

## 버전별 변경 이력

- **v2.14.0** — 플러그인 허브 콘텐츠 영역의 스크롤바를 앱 전체 톤에 맞게 얇게 스타일링(사용자 요청): `.uf-panes`와 그 내부의 모든 자손 요소(병합된 뷰어가 자기 안에서 따로 만드는 스크롤 컨테이너 포함)에 `scrollbar-width: thin`(Firefox)과 `::-webkit-scrollbar` 커스텀 스타일(8px, 반투명 흰색 thumb, 투명 track)을 적용했습니다. v2.13.1~v2.13.2에서 시도했던 `html`/`body` 전역 스크롤바 강제 방식과 달리, 이번엔 `.uf-panes` 셀렉터로만 스코프되어 있어 플러그인 허브 바깥의 다른 화면 디자인에는 전혀 영향을 주지 않습니다.

- **v2.13.2** — v2.13.1에서 추가한 html/body 스크롤바 강제 복원 스타일 제거(사용자 피드백: 전체 디자인과 어긋나 보임): `all: revert !important`로 스크롤바 모양을 강제하던 `<style>` 주입을 완전히 삭제했습니다. 이제 html/body 스크롤바는 다시 앱의 전역 CSS/테마를 그대로 따릅니다. 페이지 레벨 오버플로우 자체를 없애는 자기보정 루프(v2.13.0~v2.13.1, 0px 이하 목표 + 4px 버퍼)는 그대로 유지되므로, 스크롤이 실제로 남는 문제 자체에 대한 대응은 계속 작동합니다.
- **v2.13.1** — v2.13.0 자기보정 루프로도 여전히 남아있던 문제 확인 및 수정(사용자 스크린샷으로 확인): 실제로는 스크롤 자체보다, 병합된 M3U 플레이어가 자기 채널 목록용으로 정의한 스크롤바 커스텀 색상(굵고 튀는 색)이 스코프 없는 `<style>` 주입 때문에 `html`/`body`까지 새어나가, 이전 보정 루프가 허용하던 아주 미세한(1px 이하) 페이지 오버플로우가 그 스타일 그대로 크고 눈에 띄는 막대로 렌더링되고 있었습니다. 보정 루프의 목표를 "1px 이하 허용"에서 "0px 이하 + 4px 버퍼"로 낮췄습니다(최대 반복도 3→5회). *(html/body 스크롤바 강제 복원 스타일도 함께 추가했었으나 v2.13.2에서 제거됨 — 아래 참고.)*
- **v2.13.0** — v2.12.0 수정이 실제로는 부족했던 문제 보완(사용자 확인): `window.innerHeight - top` 공식 하나만으로 높이를 정하면, 코어 레이아웃에 우리가 모르는 요소(하단 고정 바 등)가 있거나 `window.innerHeight` 자체가 실제 가시 영역과 미세하게 다를 때 여전히 페이지 전체 스크롤이 생길 수 있었습니다(실제로 M3U 플레이어 탭에서 재현됨). 계산값을 적용한 뒤 문서 전체에 실제로 세로 스크롤이 남아있는지 직접 측정해서, 남아있으면 그 초과분만큼 우리 쪽 높이를 한 번 더 줄이는 자기보정 루프를 추가했고, `panes` 내부를 `MutationObserver`로 지켜보다가 병합된 뷰어의 비동기 렌더링 변화가 있을 때마다 다시 보정하도록 했습니다.
- **v2.12.0** — 화면 높이에 안 맞고 스크롤이 생기던 문제 수정(사용자 요청): `.uf-plugin { height: 100% }`는 부모 요소들이 전부 명시적인 height를 갖고 있어야만 실제로 동작하는데, 코어가 이 플러그인을 마운트하는 컨테이너 체인 중 하나라도 `height: auto`(내용에 따라 늘어나는 방식)이면 100%가 무너지면서 원래 `.uf-panes` 안에서만 나야 할 스크롤이 페이지 전체 스크롤로 새는 문제가 있었습니다. `script.js`가 `window.innerHeight`에서 루트 요소의 화면상 y좌표를 뺀 값을 인라인 `height`로 고정하는 최초 버전(v2.13.0에서 자기보정 루프로 보완됨). CSS 쪽에도 `max-height: 100vh`와 `overflow: hidden`을 안전장치로 추가.

- **v2.11.0** — 이미 사용 중이던 플러그인의 저장값 초기화(사용자 요청): 가이드 위반이 감지된 플러그인이 이전에 허브에 "합치기"/"숨기기"로 설정되어 있었다면, 그 `MODE_<id>__<session>` 값들을 기본값으로 되돌리고 `TAB_ORDER_<session>` 목록에서도 해당 id를 제거해 실제 DB(`PLUGIN_CONFIG_plugin_hub`가 저장된 세션)에 즉시 다시 저장합니다. 이전 버전(v2.10.0)은 화면(카탈로그/탭 목록)에서만 제외하고 저장값은 그대로 방치했는데, 그러면 나중에 다시 가이드를 준수하게 되는 순간 옛 설정이 예고 없이 되살아나는 문제가 있었습니다. p_id당 프로세스 생애주기 동안 정리는 1회만 수행하며(반복 저장 방지), 저장 세션은 `PLUGIN_CONFIG_plugin_hub`가 최근에 저장된 것으로 확인된 세션을 그대로 재사용합니다.
- **v2.10.0** — 가이드 이탈 플러그인 자동 제외(사용자 요청): 두 가지 규칙 — ① 클래스 `id`가 실제 폴더명과 일치하는지, ② 그 폴더에 `plugin version` 키를 가진 유효한 `VERSION` 파일이 있는지 — 를 검사해, 하나라도 위반하면 해당 플러그인을 허브의 탐색 대상에서 아예 제외합니다. 제외된 플러그인은 `category_tab`도 전혀 건드리지 않아 원래 자기 사이드바 탭 그대로 완전히 독립적으로 계속 동작하며, 허브 탭/설정 표/카탈로그 어디에도 나타나지 않습니다. 검사 결과는 60초 TTL로 캐시하고, 위반 시 서버 로그에 사유를 프로세스 생애주기당 1회만 남깁니다.
- **v2.9.1** — GitHub 업데이트 확인 캐싱(사용자 요청): 매 탭 마운트마다 GitHub에 요청을 보내던 것을 `localStorage`에 6시간 TTL로 캐시하도록 변경 — 캐시가 유효하면 네트워크 요청 없이 캐시된 결과로만 배지 표시 여부를 판단하고, 6시간이 지났거나 캐시가 없을 때만 실제로 GitHub를 조회한다. `localStorage`를 쓸 수 없는 환경(프라이빗 브라우징 등)에서는 캐시 읽기/쓰기가 조용히 실패하고 매번 확인하는 이전 동작으로 자연히 폴백된다.
- **v2.9.0** — 사용자 요청 반영: (1) 헤더의 "플러그인 허브" 제목/아이콘/버전 배지 글자 크기를 약 20% 키움. (2) GitHub 저장소(`https://github.com/yume-script/plugin_hub`)의 `VERSION` 파일을 탭 마운트 시 조회(raw.githubusercontent.com, CORS 허용됨)해 로컬 버전보다 최신 버전이 있으면 제목 옆에 주황색 "⬆ vX.Y.Z 업데이트 가능" 배지를 추가로 표시 — 클릭하면 GitHub 저장소로 이동. 이미 존재하던 `update_manifest`(관리자 "환경설정 > 플러그인 설정" 화면의 업데이트 버튼용, `raw_base_url: https://raw.githubusercontent.com/yume-script/plugin_hub/refs/heads/main/`)와 동일한 저장소/브랜치를 그대로 참조하며, 이 배지는 실제 파일을 교체하지 않는 순수 안내용이라 네트워크 실패/사내망 차단 시에도 조용히 무시되고 나머지 기능에는 영향 없음.

## 파일 구조

```
plugin_hub/
  __init__.py      # 제공자 노출
  plugin_hub.py     # 제공자 + 동적 config/카탈로그 + category_tab 오버라이드
  index.html        # 탭 바 + 패널 컨테이너
  style.css         # 테마 CSS 변수 연동 탭 스타일
  script.js         # 탭 목록 조회 + 뷰어 직접 마운트/클린업
  settings.html     # 설정 페이지 카드형 UI 골격
  settings.css      # 카드 그리드 스타일
  settings.js       # 카탈로그 fetch + 카드 렌더 (저장은 코어 폼 submit 이용)
  VERSION           # 버전 파일
```

## 주의 / 설계 메모

- 탭·카드 목록은 팩토리 디스커버리 기반 동적 생성 — 뷰어 설치/삭제 시 자동 반영 (자기 자신 제외).
- settings.js의 체크박스 `name`이 설정 키와 동일하므로 코어의 "설정 저장" 버튼이
  그대로 값을 수집·저장합니다 (별도 저장 API 불필요).
- gunicorn 1워커 전제: category_tab 런타임 오버라이드는 프로세스 메모리 기준입니다.
- `.py` 변경은 컨테이너 재시작 필요, html/css/js는 bind mount로 즉시 반영.
